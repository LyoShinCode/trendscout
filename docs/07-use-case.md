# UC-01 · Обработка алерта прорыва

**Актор:** A&R-менеджер лейбла.
**Предусловие:** алерт в статусе NEW; менеджер аутентифицирован и подписан на регион/тип.

## Основной сценарий
1. Менеджер открывает алерт из уведомления.
2. Система показывает тип, правило, confidence, provisional-флаг, audit trail, карточку артиста (ISRC, доступность каталога).
3. «Взять в работу» → IN_REVIEW, запись в audit trail.
4. «Подтвердить» → CONFIRMED; задача букингу с регионом из алерта.

## Альтернативы
- A1 (шаг 4): отклонение с причиной (≤ 500 символов) → REJECTED.
- A2 (любой шаг): FR-04 отозвал алерт по поздним данным → REJECTED + revised, действия заблокированы, уведомление.
- A3 (шаг 3): алерт provisional → баннер «данные неполные», рекомендация дождаться ревизии.

## Постусловие
Финальный статус; полный audit trail; при CONFIRMED — задача букингу.

## Гарантии
Переходы валидируются сервером (409); каждое изменение фиксируется в AlertNote.
