# Требования

## Бизнес-требования
- **BR-01:** находить перспективных артистов до того, как их заметит рынок.
- **BR-02:** отличать устойчивый рост от скоропортящегося хайпа.
- **BR-03:** алертам можно доверять — ложные срабатывания объяснимы и отзываемы.

## FR-01 · SLEEPER
**Триггер:** завершён недельный пересчёт RegionalChart региона R за период P.
**Условие:** артист в Top-N **И** не входил в Top-popular_rank за lookback (24 мес) **И** каталог доступен ≥ 12 мес **И** наблюдаемая база < 50 000.
**Действие:** создать Alert(type=SLEEPER, status=NEW), уведомить подписчиков.
- AC-01.1: 23 мес вне Top-popular_rank, попал #4 → алерт создан. → `test_ac_01_1_sleeper_fires`
- AC-01.2: был #40 10 мес назад → алерт НЕ создан. → `test_ac_01_2_recent_top50_blocks`
- AC-01.3: пороги меняются конфигурацией без пересборки. → `test_ac_01_3_thresholds_configurable`

## FR-02 · NEWCOMER
**Условие:** дебют ≤ 6 мес **И** позиция ≤ Top-N **И** ранее вне Top-popular_rank.
- AC-02.1: дебют 5 мес, первое попадание #4 → алерт. → `test_ac_02_1_newcomer_fires`
- AC-02.2: дебют 7 мес → не NEWCOMER. → `test_ac_02_2_debut_7_months_not_newcomer`

## FR-03 · VIRAL + скоропортящийся потенциал
**Условие:** активное MediaEvent **И** рост ≥ ×2.5 к скользящей медиане 4 недель **И** позиция ≤ Top-N.
**После end_date:** мониторинг затухания N недель; падение > 40% от пика → «окно возможностей ≤ 2 нед».
- AC-03.1: рост ×3+ при активном событии → алерт. → `test_ac_03_1_viral_with_media`
- AC-03.2: тот же рост без события → VIRAL не создан. → `test_ac_03_2_no_media_no_viral`

## FR-04 · Полнота данных и ревизия
**Условие:** полнота платформ < 100% в рамках SLA 72ч → чарт provisional, алерты provisional с пониженным confidence.
**Действие при поздних данных:** пересчёт; условие не выполняется → автоматический REJECTED + revised + уведомление; выполняется → confidence пересчитан.
- AC-04.1: сценарий «Яндекс +72ч» → provisional → отзыв. → `test_ac_04_1_lag_provisional_then_revoke`

## FR-05 · Guard: покупка прав
**Условие:** наблюдаемая база < порога, но истинная ≥ порога **И** available_since площадки свежее catalog-порога.
**Действие:** алерт НЕ создаётся; запись в журнал правил.
- AC-05.1: обнуление счётчиков звезды → ложный SLEEPER предотвращён. → `test_ac_05_1_rights_guard_prevents`

## Нефункциональные требования
| ID | Требование | Метрика |
|---|---|---|
| NFR-01 | Свежесть данных | SLA батча ≤ 72ч, иначе provisional |
| NFR-02 | Конфигурируемость | смена порога ≤ 1 мин, без redeploy (PUT /config) |
| NFR-03 | Объёмы | 50 млн событий/нед в бою; партиции по месяцам; retention 24 мес |
| NFR-04 | Латентность детекции | ≤ 5 мин после пересчёта чарта |
| NFR-05 | Наблюдаемость | журнал каждого решения правила; audit trail алерта |
