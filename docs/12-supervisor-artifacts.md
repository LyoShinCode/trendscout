## Короткий ответ

Показывать **шесть артефактов** в таком порядке: пояснительная записка → живой стенд →
трассировка требований в тесты → модель данных с журналом решений → контракт API →
план развития. Всё остальное — по запросу.

## 4. Модель данных и журнал решений

**Файлы:** `docs/02-domain-model.md` (ER-диаграмма Mermaid + ADR D-01…D-11),
`backend/app/models.py`

Показать три решения и объяснить, почему они приняты:

| Решение | Почему |
|---|---|
| D-02: позиции чарта реляционно, не JSON | иначе невозможен SQL-запрос по динамике позиций, а на нём держатся оба правила |
| D-03: связи M:M с атрибутами | `available_since` делает «каталог давно доступен» измеримым |
| D-06 / D-09: истинная и наблюдаемая база разделены | признак «база за всю историю» дисквалифицировал сам прорыв |

**Что сказать:**
> «Часть решений появилась не из головы, а из валидатора: он проверяет не только количества
> строк, но и согласованность демо-набора с бизнес-правилами. Он поймал расхождение —
> демо-сигнал ссылался на правило, которому данные не удовлетворяли. Каждое такое решение
> зафиксировано в ADR.»

## Формулировки для сильных вопросов

**«Почему не машинное обучение?»**
> Размеченной выборки прорывов нет, а объяснимость для бизнеса критична: менеджер должен
> видеть, почему сигнал создан. Пороги калибруются по истории; ML — следующий этап
> на тех же признаках с сохранением объяснений.

**«Данные настоящие?»**
> Нет, синтетические с фиксированным зерном — это осознанное решение для воспроизводимости
> и отсутствия правовых ограничений. Подключение реальных API — ближайший этап,
> источник отделён адаптером.

**«Что здесь ваше, а что фреймворк?»**
> Фреймворк даёт транспорт и ORM. Мои — доменная модель и её решения, алгоритм детекции
> с признаками и предохранителями, требования с приёмочными критериями, трассировка в тесты,
> контракт, процесс BPMN, валидатор согласованности данных и интерфейс.

**«Как проверялась корректность?»**
> Тремя контурами: валидатор данных и инвариантов модели, двенадцать приёмочных автотестов
> по критериям, контрактные тесты API на изолированной базе. Плюс сборочная проверка
> доступности всех эндпоинтов и файлов интерфейса.
